wikifn-fstar

Wikifunctions composition analysis prototype

A small repository for importing pinned Wikifunctions ZObjects, running a prototype composition interpreter, and checking an initial F* model.

What works now

  • Canonical ZObject JSON parsing and normalization.
  • Basic structural checks for local snapshots.
  • Revision and SHA-256 digest recording for imported objects.
  • A vendored 20260801 Wikifunctions dump and local SQLite composition graph index.
  • A deliberately named junk proof-of-concept JavaScript evaluator for a small `Z14K2` composition subset.
  • A bounded Wikifunctions analyzer that reports composition-closed graphs and open frontiers.
  • An initial F* model and primitive kernel checked by `make fstar-check`.
  • A real F* to OCaml to JavaScript extraction demo for checked primitives, selected generated composition IR, and direct specialized functions.

What it is not

  • It is not a proof that arbitrary Python or JavaScript `Z16` implementations are correct.
  • It is not yet a complete Wikifunctions evaluator.
  • It is not yet using F* as the format of record.
  • It is not yet a Low*/KaRaMeL C extraction target.
  • The deliberately named junk JavaScript composition evaluator is a pre-F* prototype, not extracted F* code.
  • Closure claims are relative to the fetched corpus and the selected primitive policy.

Actual F* extraction demo

This extracts the checked primitive kernel, `Wikifn.Primitives`, a small F* composition interpreter, generated F* IR for selected pinned compositions, and direct specialized F* functions for the same selected paths. It compiles an OCaml runner and emits JavaScript with `js_of_ocaml`. It does not yet parse arbitrary canonical ZObject JSON at runtime.

Toy composition demo

        
The local fixture defines recursive addition using `if`, `is_zero`, `successor`, and `predecessor`.

        
add(x, y) =
  if is_zero(y)
  then x
  else add(successor(x), predecessor(y))

        

          In ordinary counting terms, `successor(n)` is the next number and `predecessor(n)`
          is the previous number. The demo moves one count from the second argument to the
          first until the second argument is zero.
        

        
add(2, 2)
add(3, 1)
add(4, 0)
4

        
Run:

        
node ./bin/wikifn.js eval-example --trace --profile

        
The result value is a Wikifunctions-style natural number:

        
{
  "Z1K1": "Z10",
  "Z10K1": "4"
}

Next grounding frontier

        

          The local SQLite graph says the next useful F* primitive work is mostly
          lists, string joins/equality, booleans, and natural-number arithmetic.
          These are high-reuse leaves in existing compositions.
        

        

          
            

              Priority
              Plain name
              Wikifunctions ID
              Why it matters
            

          
          
            

              1
              List head/tail/empty/prepend/length
              Z811, Z812, Z813, Z810, Z12681
              These appear across hundreds of composition implementations and unlock recursive list algorithms.
            

            

              2
              String concatenate, equality, join-list
              Z10000, Z866, Z21394, Z12899
              Needed for readable text-generation demos, including many language and formatting functions.
            

            

              3
              Boolean operators
              Z10174, Z10184, Z10216
              Small, precise F* specs; common in validation and branching-heavy compositions.
            

            

              4
              Natural-number arithmetic
              Z13521, Z13522, Z13578, Z13582, Z13539
              Necessary for algorithmic demos beyond strings, including recursive sequence and counting functions.
