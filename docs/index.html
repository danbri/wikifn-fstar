wikifn-fstar

Wikifunctions compositions, checked by F*

2,430 real Wikifunctions compositions, mechanically translated into F*, checked by F*, extracted to OCaml, compiled to JavaScript, and runnable in a browser. 211 of them pass every Wikifunctions tester this project can read.

  • An F* evaluator with lists, pairs, function references, and the LISP core: cons, car, cdr, null?, if, map, filter, fold.
  • A ZObject model, identifier parsing, and canonical-form normalisation, all as checked F* definitions rather than assumptions.
  • A generator that translates pinned Z14K2 compositions into F*, recording revision and digest for each.
  • A fixpoint closure analysis over the whole corpus in under a second.
  • Every generated body also printed as an s-expression by a checked F* module, and rendered back to canonical Wikifunctions composition data.
  • Any function exportable as a self-contained Scheme program that runs in an off-the-shelf Scheme.
  • A vendored 20260801 dump, local SQLite composition graph index, and digest-pinned object cache.

What it is not

  • It is not a proof that arbitrary Python or JavaScript `Z16` implementations are correct.
  • Completing evaluator coverage is the current priority; unsupported ZObject forms and foreign-code boundaries are still reported explicitly.
  • The primitives are authored F*, not derived from Wikifunctions. They are a claim about what Wikifunctions means, checked against its own testers rather than proved.
  • There is no object store, so references in argument position are refused rather than resolved.
  • Records, errors, and monolingual text are not yet values.
  • Deep recursion exhausts fuel rather than returning an answer.
  • It is not yet a Low*/KaRaMeL C extraction target.
  • The deliberately named junk JavaScript composition evaluator is a pre-F* prototype, not extracted F* code.
  • Closure claims are relative to the fetched corpus and the selected primitive policy.

Next grounding frontier

Records, value-by-key, object equality, the codepoint conversions and the higher-order list functions are now grounded, so the four that used to head this list are down to two. Re-measured with make closure, a fixpoint over the call graph; the count is how many of the 4,970 corpus functions each one still gates.

Priority Plain name Wikifunctions ID Blocks Why it matters
1 Errors as values, and the functions around them Z5, Z851, Z850, Z853 1,449 / 1,353 / 1,446 Throwing, catching and reading an error. Also what most testers need: 3,122 tester cases are skipped today because their validator cannot run.
2 Quoting and reflection Z805, Z899, Z29267 1,449 / 1,320 / 1,446 Reify, unquote, and a quoted reference. Needed before any function that treats another function as data can run.
3 String from Type Z22764 1,455 The single largest blocker by count. Rendering a type as text, which needs types to be values.
4 Fetch persistent object Z828 1,446 Reading a ZObject by reference. There is no object store here, so a reference is refused rather than resolved.

Done since this list was last written: Z803 value by key, Z16829 type of object, Z13052 object equality, Z22693 and Z22717 codepoint conversions, Z12668 and Z12961 reverse and append, Z13546 natural division, and records as values. Closure over the engine's 53 primitives is now 936 functions without recursion and 1,168 with.
