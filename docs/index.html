wikifn-fstar

Wikifunctions composition analysis prototype

A small repository for importing pinned Wikifunctions ZObjects, running a prototype composition interpreter, and checking an initial F* model.

What works now

  • Canonical ZObject JSON parsing and normalization.
  • Basic structural checks for local snapshots.
  • Revision and SHA-256 digest recording for imported objects.
  • A vendored 20260801 Wikifunctions dump and local SQLite composition graph index.
  • A deliberately named junk proof-of-concept JavaScript evaluator for a small `Z14K2` composition subset.
  • A bounded Wikifunctions analyzer that reports composition-closed graphs and open frontiers.
  • An initial F* model and primitive kernel checked by `make fstar-check`.
  • A real F* to OCaml to JavaScript extraction demo for checked primitives, selected generated composition IR, generated direct F* functions, and direct specialized functions.

What it is not

  • It is not a proof that arbitrary Python or JavaScript `Z16` implementations are correct.
  • Completing evaluator coverage is the current priority; unsupported ZObject forms and foreign-code boundaries are still reported explicitly.
  • It is not yet using F* as the format of record.
  • It is not yet a Low*/KaRaMeL C extraction target.
  • The deliberately named junk JavaScript composition evaluator is a pre-F* prototype, not extracted F* code.
  • Closure claims are relative to the fetched corpus and the selected primitive policy.

Next grounding frontier

The local SQLite graph says the next useful F* primitive work is mostly lists, string joins, object access, and higher-order list traversal. These are high-reuse leaves in existing compositions.

Priority Plain name Wikifunctions ID Why it matters
1 List head/tail/empty/prepend/length Z811, Z812, Z813, Z810, Z12681 These appear across hundreds of composition implementations and unlock recursive list algorithms.
2 String join-list and delimiter joins Z21394, Z12899 Needed for readable text-generation demos after the basic string primitives.
3 Object access Z803, Z805, Z808, Z22475 Large unlock, but it needs explicit ZObject/key semantics rather than a scalar primitive.
4 Higher-order list functions Z873, Z876, Z12696 High reuse, but requires first-class function values, equality policy, and trace/fuel semantics.
