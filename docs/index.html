wikifn-fstar

Wikifunctions compositions, checked by F*

745 real Wikifunctions compositions, mechanically translated into F*, checked by F*, extracted to OCaml, compiled to JavaScript, and runnable in a browser. 172 of them pass every Wikifunctions tester this project can read.

  • An F* evaluator with lists, pairs, function references, and the LISP core: cons, car, cdr, null?, if, map, filter, fold.
  • A ZObject model, identifier parsing, and canonical-form normalisation, all as checked F* definitions rather than assumptions.
  • A generator that translates pinned Z14K2 compositions into F*, recording revision and digest for each.
  • A fixpoint closure analysis over the whole corpus in under a second.
  • Every generated body also printed as an s-expression, and rendered back to canonical Wikifunctions composition data.
  • A vendored 20260801 dump, local SQLite composition graph index, and digest-pinned object cache.

What it is not

  • It is not a proof that arbitrary Python or JavaScript `Z16` implementations are correct.
  • Completing evaluator coverage is the current priority; unsupported ZObject forms and foreign-code boundaries are still reported explicitly.
  • The primitives are authored F*, not derived from Wikifunctions. They are a claim about what Wikifunctions means, checked against its own testers rather than proved.
  • There is no object store, so references in argument position are refused rather than resolved.
  • Records, errors, and monolingual text are not yet values.
  • Deep recursion exhausts fuel rather than returning an answer.
  • It is not yet a Low*/KaRaMeL C extraction target.
  • The deliberately named junk JavaScript composition evaluator is a pre-F* prototype, not extracted F* code.
  • Closure claims are relative to the fetched corpus and the selected primitive policy.

Next grounding frontier

Lists and higher-order list functions are now implemented. The closure analysis says these four are what gate the most remaining functions, counted as how many functions each one blocks.

Priority Plain name Wikifunctions ID Why it matters
1 Value by key Z803 Blocks about 2,700 functions. Needs records as values.
2 Throw Error Z851 Blocks about 2,300. Needs errors (Z5) as values.
3 Reify and Unquote Z805, Z899 Blocks about 2,200 each. Reflection over the object graph.
4 Codepoint list conversions Z22693, Z22717 Blocks about 2,200. Bridges text and typed lists.
